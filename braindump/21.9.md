I've been cleaning toilet and flat yesterday, so that felt like nice opportunity to try the loop.

Prototype was build on 3 apps without me doing anything: 
- Basic pomodoro timer
- Google keep notes
- Townscraper 

I've created to-do list in google keep notes, started the timer in pomodoro app, and after each pomodoro, checkout out items from to-do list.
For each item completed, I've added a building in townscraper, went for a smoke and when I came back, repeated the same thing. 
I've managed to do 4 cycles and complete 6 tasks. It felt quite satisfing, even though it was missing a few things.

So the basic gameloop can be described as
Choose task -> focus -> earn one action -> build -> continue or complete

And it felt somehow rewarding.
Upon my 100minutes of work, I've come to face 1 design problem with the concept. 1st being, when to reward user ? Is it after each pomodoro window or is it after completed to-do task ? If I've finished multiple tasks during one focus window, should I be rewarded multiple times ? 
My idea is that app should be persisting and showcasing the work you've done (and tag each object by date + task ideally), so rewarding focus sounds counterintuitive. 
On the other hand, I'm used to splitting tasks and issues to countless sub tasks, so this would bloat the app with 'fake tasks' and I don't really want to introduce something like Epics, as that sounds like it's going astray from original idea. 
I can perhaps add a simple optional 'Project'.

So the structure could be Project (otpional) -> Task -> Sub task (optional)
Now, task should be optional as well, but then I have to figure out how to reward focus. This could be solved by prompt after focus time without task, asking user if he achieved something worthwile in his focus time. 
In theory, that could work, but the basic loop is adjusted a little:

With task:
focus -> Choose task -> earn one action for finished task -> build -> repeat

Without task / user agreed: 
focus ->  Prompt user if he wants to build after focus window -> earn one action -> build -> repeat

Without task / user disagreed: 
focus ->  Prompt user if he wants to build after focus window -> repeat

Now, upon revisiting this, this sounds utterly rubbish. I musn't and don't want to build simplified project management tool with statues, projects, tasks and subtasks. 
What I want to create is not something that managees work inside the app, but rewards small progress and visually showcases it.

This sounds cheap, but the user prompting can be solution.
"What are you working on?" before timer starts.
"Did you finish it?" after timer ends. 
Yes: earn one building action.
Not yet: continue another session or stop without a reward.
I finished something else: write what it was and earn one action.

The problem this creates is what is user finishes his work before timer runs out ?
We have 3 possible "gameplay" loops here:
1) Ideal 
Set intention -> focus -> confirm completion -> build -> repeat
2) More than one task is finished
Set intention -> focus -> finish -> queue reward -> choose next intention -> continue -> build -> repeat
3) No task is finished
Set intention -> focus -> finish early -> confirm -> continue working or stop -> build -> repeat
